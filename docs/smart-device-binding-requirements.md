# 智能设备绑定与查询需求（小佩首期）

版本：2026-10-23 · 已确定账号密码方案，待设计／接口实现

本稿用于下一步出设计稿，暂不实施页面或修改服务端。核对范围为小程序当前源码与 `/Users/lanchenghao/Documents/projects/chongxi`（HEAD `fe21854`）的接口、服务和文档。以下“已实现”指本地源码确认，未登录小佩账号、未执行设备采集，也未验证线上部署或机型兼容性。

## 1. 核对结论

服务端已有小佩设备读取与快照采集能力，但尚未形成普通用户在小程序中连接自己小佩账号、选择设备、绑定宠物、查询和解绑的完整链路。

- 小程序：首页“今日状态”下已有“绑定智能设备”入口，目前只打开“硬件接入准备中”的说明弹层，状态固定为“未连接”。没有设备列表／详情页面或设备 API 对接。
- 服务端：`/api/petkit` 已注册，支持设备列表、快照采集、快照索引、进食／出粮事件。全部走 `admin_required`，允许指定工作台角色或 `X-Admin-Token`，不支持小程序用户 Bearer 身份直接访问。
- 账号：采集器读取服务器环境中的 `PETKIT_USERNAME/PETKIT_PASSWORD` 与共享 session 文件，默认 CN 区域；没有按小程序用户隔离的小佩账号连接管理。
- 绑定：健康引擎采集成功后会登记 `PetDevice` 并关联一个 `pet_id`，已阻止采集时静默改绑其他宠物，但没有普通用户绑定／解绑／归属校验接口。该表没有用户及小佩账号连接字段，不能直接作为用户设备管理模型。
- 健康数据：桥接返回 `synced_metrics: {}`、`mapping_status: "pending"`。目前只保存原始快照并登记设备，尚未启用硬件字段到健康指标的映射。
- 文档：未找到独立的小佩用户接入接口文档；现有说明主要在路由／服务注释。`docs/guardian-1020-api.md` 明确 `reported_device` 只是用户手填设备统计，无原生绑定认证。它与新采集能力属于不同层级，不能据此认定小程序已经接入。

## 2. 目标与首期范围

让用户从首页连接自己的小佩账号，查询可用设备，选定设备关联宠物，并查看设备状态、最近同步时间和已验证的设备明细。

首期建议支持小佩智能喂食器、智能饮水机，具体可绑定型号须由服务端能力清单和实机验证决定。账号列表中出现的其他类型显示“暂不支持”，不因为能枚举就承诺可用。猫砂盆本期不开放绑定。

“绑定”指将小佩账号中已有设备连接到宠析并建立关联；首次配网、添加硬件和网络配置仍在小佩 App 完成。本期不做蓝牙发现、扫码配网、远程出粮、设备设置、视频播放、历史健康曲线或自动填充首页今日次数。

## 3. 用户主流程

首页入口 → 登录宠析（未登录时）→ 我的设备 → 添加小佩设备 → 输入小佩 App 用户名和密码 → 勾选知情同意 → 连接小佩账号 → 查询账号内设备 → 选择设备 → 关联宠物／确认使用方式 → 确认绑定 → 设备详情。

建议首期一次绑定一台，可反复添加；一个用户可绑定多台，一个宠物可关联多台。小佩账号连接与单台设备绑定分别管理：账号连接成功不等于设备绑定成功；设备绑定成功不等于首次数据同步成功。

### 3.1 首页入口

- 保留现有“今日状态”下的位置。无绑定时显示“绑定智能设备”；有绑定时显示“我的设备”，附“已绑定 N 台”。N 按当前宠物关联设备计算，并与设备页筛选一致。
- 不再用固定“未连接”概括所有状态。已绑定但同步失败时显示“同步异常”；尚未获得实时在线字段时，不显示“在线／离线”的确定判断。
- 当前宠物没有关联设备，但账号有其他设备：进入设备页后可切换“全部设备”，不可误显示整个账号没有设备。
- 未登录可查看品牌介绍，连接／查询私有设备前要求登录；登录后返回原流程。没有宠物档案时允许先浏览设备，在确认绑定前引导创建宠物，返回后保留设备选择。

### 3.2 我的设备

- 默认展示当前宠物关联设备，提供“全部设备”视图和“添加设备”操作。
- 卡片展示：设备名称、品牌／类型、关联宠物、使用方式、最近一次成功同步时间、同步状态。型号和硬件在线状态仅在服务端有可靠字段时展示。
- 空态：“还没有绑定智能设备”，主按钮“添加小佩设备”，保留手动记录入口。
- 查询失败与真正空列表分开；失败显示重试，有缓存时保留旧卡片并标明更新时间。
- 点击卡片进入详情；刷新列表只查询当前绑定信息，不为每张卡片启动一次实时采集。

### 3.3 添加与账号连接

- 品牌页先提供“小佩 PETKIT”，说明“请先在小佩 App 中完成设备添加。连接后可读取设备信息与记录”。
- 连接说明列明读取范围、账号用途和解除连接入口。小程序不携带管理员令牌，不展示服务器默认账号的设备。
- **已确定使用小佩 App 用户名与密码连接。** 页面提供用户名输入框、默认隐藏的密码输入框及显隐按钮，不提供“记住密码”。用户名不限制为手机号；密码不做 trim 或内容改写。
- 表单下小字：“用户名和密码仅用于本次小佩账号验证，宠析不会持久保存。连接后将保存用于查询设备的登录会话凭证。”下接可点击的《小佩设备连接知情同意书》和《隐私协议》链接，全文见配套文档。
- 独立勾选项：“我已阅读并知情同意《小佩设备连接知情同意书》，并已了解《隐私协议》中的设备连接说明。”默认不勾选，打开链接不自动勾选；不同意仍可使用手动记录等其他功能。
- 用户名、密码均已填写且已勾选时，才启用“同意并连接小佩账号”。提交前再次校验；后端验证同意状态与文档版本，未同意不得向小佩发起认证。协议更新涉及处理目的、方式或种类变化时重新取得同意。
- 点击链接阅读时不丢失页面流程；进入后台或离开认证流程时清空密码，提交结果返回后清空用户名和密码（失败后重新输入）。禁止表单持久化、埋点采集和页面回放记录凭据。
- 认证成功后只保留隔离、加密的必要会话凭证，按连接查询设备；不得保存用户名、密码或可替代密码的派生凭据。会话失效需用户重新输入并勾选，不使用后台保留的密码自动重登。具体实现约束见配套知情同意文档。
- 连接成功后查询候选设备；已有有效连接直接查询。过期时展示“请重新连接小佩账号”，保留已有绑定关系。
- 无设备：提示确认小佩 App 内已添加设备、账号／区域正确，提供“重新查询”和“更换账号”。查询失败不能显示成“未找到设备”。

### 3.4 选择设备与确认绑定

- 列表展示设备名称、类型／可用型号、支持状态、绑定状态；不要求用户手填 device_id。
- 已绑定当前宠物：标记“已绑定”，可查看详情，重复提交返回同一绑定结果。
- 已关联本账号其他宠物：提示已有归属，首期通过解绑后重新绑定变更，不静默覆盖。
- 不属于当前连接、已被其他用户占用或已从小佩账号移除的设备：服务端拒绝绑定；不泄露他人身份或宠物名称。
- 确认页展示设备、选定宠物和使用方式：“仅这只宠物使用 / 多宠共用 / 不确定”。不得默认认定单宠，建议默认“不确定”。
- 首期每台设备关联一个宠物档案作为管理入口；多宠共用仍标记为共享设备，不表示记录属于该宠物个人。完整家庭多宠关联留待后续。
- 提交期间禁用重复点击；失败保留选择并可重试。成功后进入详情，显示“绑定成功，正在同步”；首次同步失败显示“已绑定，首次同步失败”，提供重试，不回滚为未绑定。

### 3.5 详情、同步与解绑

- 详情内容：设备名称／类型、关联宠物、使用方式、最近成功同步时间、数据时间、可用状态字段、记录明细。采集时间与设备源数据时间分别表达，避免刚采集的旧数据被标成实时。
- 手动“同步数据”：提交后台同步任务；显示进行中、成功或失败。重复点击复用进行中任务；离开页面不取消绑定，返回后可查询任务状态。
- 同步失败保留上次成功数据并标注“更新失败，当前为上次数据”。没有历史数据时提示“暂未获取到数据”，不能填 0。
- 解绑需确认：“解除后将停止在宠析同步此设备，不会删除小佩 App 中的设备。”解除单台绑定不影响同一连接下其他设备。
- 断开小佩账号连接需单独确认，明确受影响设备；停止该连接的后续采集并解除其有效绑定，清理凭据／会话。提供“同时删除已同步设备历史数据”的选择；保留时只供历史查看，保留原来源和归属，不重新归入后来绑定的宠物。清理范围及期限与隐私协议一致。

## 4. 数据展示规则

喂食器：当前代码能抽取进食事件、进食开始／结束时间和时长，出粮事件及各粮仓出粮数值；部分机型可返回粮量状态、干燥剂剩余天数。按设备能力展示，缺失字段隐藏或显示“暂无数据”。事件时间统一北京时间；`eat_sec` 是结束减开始，不能用视频片段时长 `clip_sec` 代替。

饮水机：部分机型可读取滤芯比例、缺水提醒、电量等。水泵运行时间、净水量等候选字段不能被解释为宠物实际饮水量或饮水次数。缺少饮水事件契约时，不设计可用的饮水记录列表。

出粮份数不等于克数，出粮不等于吃掉；单位和字段含义由后端按已验证机型提供。原始 `eat_weight` 等字段在未确认单位、有效性前不作为核心消费指标。

账号授权状态、绑定状态、同步状态、硬件在线状态必须分开。当前 `PetDevice.connection_status = connected` 是采集成功后写入的登记值，不能证明硬件此刻在线。

多宠共用／归属不明的记录只能作为设备级信息。即使用户选择单宠使用，当前映射仍为 pending，本期也不写入首页健康次数，不与手填记录相加或覆盖。设备无记录、设备不支持、未同步、同步失败四种情形不得都显示为 0。

## 5. 现有接口核对（管理员接口，非小程序可直接使用）

### GET /api/petkit/devices

返回 `{ok, devices: [{key, device_class, name}], session_reused}`。查询服务器配置的小佩账号，不登记绑定、不写快照库，但会访问上游并更新会话缓存。没有用户归属、型号、稳定在线状态和宠物关联字段。

### POST /api/petkit/collect

请求 `{device_id?, hints?}`，hints 默认 water。返回快照及可能的 summary，写 SQLite 与导出 JSON。明确选定设备必须传 device_id；不传时采集器按饮水设备匹配，hints 是候选字段筛选规则，不能用 hints=feeder 代替指定喂食器 ID。

响应含快照 ID、设备信息、采集时间、源数据时间、候选字段和内部诊断等。它不是稳定的用户详情契约，需服务端归一化后供小程序使用，不能透传文件路径、stdout、原始候选字段或凭据相关错误。

### GET /api/petkit/snapshots?device_key=...&limit=50

返回 `{ok, snapshots}`，limit 限制在 1–500。仅含 id、captured_at_utc、device_key、device_class、device_name、payload_sha256，不返回 raw_json 或摘要值。不能用该接口直接渲染历史健康图表／完整设备详情，也没有按日期分页契约。

### GET /api/petkit/events?device_id=...&kind=eat|feed

必填 device_id，kind 默认 eat。**每次请求都会实时采集并落快照**，不是轻量缓存查询。返回 `{ok, device_id, kind, count, events}`，目前无日期筛选／分页／完整历史保证。空 events 也可能是上游不提供或快照解析不可用，不能直接认定当天发生 0 次。

### POST /api/pet-health/collect-and-analyze

请求 `{pet_id, device_id, target_date?, attribution_status?}`，归属默认 shared，实时采集仅允许当天。采集后登记 PetDevice，再调用分析。当前 sync 中明确返回空 synced_metrics 和 pending 映射；接口名称／注释中的“落日指标”不能当成当前实现已完成的证据。该接口也需要管理员权限。

错误：petkit 路由将参数错误转为 400、采集异常为 502、其他异常为 500；鉴权还可能返回 401／503。当前错误文字偏技术诊断，未提供完整业务错误码。

## 6. 小程序待新增接口建议（未实现，路径供评审）

统一使用 `/api/miniprogram` 前缀和现有 Bearer 登录身份。身份从会话获取，不能信任客户端传入的 user_id。下列契约是需求提案，不能作为现有接口调用。

1. `GET /device-connections`：返回当前用户品牌连接、授权状态和系统生成的连接标识；不保存或返回用户输入的用户名（包括脱敏副本）。
2. `POST /device-connections/petkit`：建立／重新认证连接；请求 `{username, password, consent: {accepted: true, notice_version, privacy_version}}`。后端先校验当前文档版本与同意，再通过 HTTPS 验证小佩账号，凭据仅在本次处理期间使用。返回 connection_id、状态，不回显账号密码；服务端记录用户、文档版本、服务端同意时间及撤回状态。
3. `DELETE /device-connections/{connection_id}`：断开账号连接，返回受影响绑定处理结果。
4. `GET /device-connections/{connection_id}/devices`：获取候选设备，返回服务端可校验的设备标识、类型、能力和本账号绑定状态；查询较慢时支持后台发现任务，不阻塞页面长请求。
5. `POST /device-bindings`：提交 `{connection_id, vendor_device_id, pet_id, attribution_status}`；服务端校验设备属于连接、宠物属于当前用户及冲突状态，幂等创建，返回 binding_id 和首次同步任务。
6. `GET /device-bindings?pet_id=...`：查询绑定设备摘要；省略 pet_id 查询账号全部设备。
7. `GET /device-bindings/{binding_id}`：返回标准化详情，包括 capabilities、binding_status、auth_status、sync_status、online_status（允许 unknown）、last_success_at、source_time、可用指标及单位。
8. `POST /device-bindings/{binding_id}/sync` 与 `GET /device-sync-jobs/{job_id}`：创建／复用同步任务并查询结果；任务终态区分成功、失败及数据尚不可用。
9. `GET /device-bindings/{binding_id}/events?kind=...&cursor=...`：查询已同步事件缓存，返回可用时间范围、分页信息、数据有效性；不在 GET 中重复实时采集。
10. `DELETE /device-bindings/{binding_id}`：解除单台绑定，重复调用结果一致；停止后续采集与宠物数据关联。

共同要求：绑定／详情／事件／任务／解绑均校验当前用户归属；会话和快照按连接隔离，用户名与密码不持久保存，服务端预配账号仅供内部验证。PetDevice 与小程序宠物档案的 ID 及权限关系需明确映射，不能仅凭字符串 pet_id 建立关系。

业务错误需区分：未登录、授权过期、设备不属于该连接、绑定冲突、不支持的型号、设备已移除、上游超时、限流、解析不可用。接口返回稳定错误码与可读提示，前端分别提供登录、重连、重查、重试等操作。

现有小程序请求超时为 30 秒，采集子进程超时上限为 180 秒且受进程内锁串行化约束。用户流程应采用任务与缓存；多进程部署还需共享队列／锁、限流及任务去重，不能靠延长前端超时完成接入。

## 7. 设计稿交付清单

1. 首页入口：未绑定、已绑定、同步异常；有其他宠物设备的情况。
2. 我的设备：空态、加载、正常列表、多设备、查询失败且有旧数据。
3. 品牌介绍／连接说明：小佩支持范围、配网前置说明、读取权限说明。
4. 账号密码页：用户名、密码显隐、小字承诺、两份文档链接、默认未勾选的知情同意、按钮禁用／启用、认证中、密码错误、授权过期；知情同意书全文页及隐私协议设备连接章节。
5. 可选设备列表：可绑定、已绑定、其他宠物占用、不支持、无设备、查询失败。
6. 绑定确认：宠物选择、无宠物引导、单宠／共享／不确定、提交中及失败重试。
7. 设备详情：喂食器与饮水机各一版；首次同步中、首次失败、有数据、旧数据、字段缺失；进食／出粮明细仅在能力支持时出现。
8. 解绑和断开账号连接确认弹窗，以及成功反馈。

设计重点：让用户能区分“已绑定”和“有可用数据”；能找到重新连接／重新同步；保留手动记录路径。不要承诺“连接即自动获得饮水量／健康结论”。

## 8. 验收标准与待确认项

上线验收：

- 未勾选、缺少同意或协议版本不匹配时，前后端均阻止认证；阅读链接不触发勾选，撤回同意后停止设备访问。
- 成功、失败、超时、取消路径均不把用户名／密码写入本地存储、数据库、文件、请求日志、错误追踪或任务队列；会话缓存不夹带账号密码字段。通过使用专用测试凭据检查日志与落盘文件验证。
- 认证成功后使用会话查询设备列表、详情和记录；会话失效提示重新输入，无后台密码重登。当前共享 env/session 采集器必须完成改造后才能上线“不保留”承诺。

- 未登录无法读取私有设备；A 用户无法通过替换 connection_id、binding_id、pet_id 或 job_id 读取／操作 B 用户的数据。
- 同一用户重复绑定不产生重复记录，跨宠物冲突不会静默改绑；解绑后在途任务不能重新建立有效绑定或写入新的宠物归属。
- 多设备、无设备、不支持型号、授权过期、上游超时均有正确页面状态；查询失败不清空已有绑定，刷新不导致重复采集风暴。
- 首次同步失败仍显示已绑定；旧数据明确标时，缺失值与零可区分，不把采集成功当成硬件在线。
- 饮水机运行字段不进入宠物饮水统计，出粮份数不转换成摄入克数，共享设备不生成单宠结论；现有手填数据保留。
- 解绑设备不操作小佩硬件，断开账号连接不影响其他用户；退出登录／切换账号清理私有页面缓存。
- 真实小佩账号至少验证一台目标喂食器及一台目标饮水机，记录具体型号、支持字段、事件时间范围和重新认证行为后，才公布支持范围。

设计前可以采用的默认方案：一次绑定一台；设备管理入口随当前宠物筛选，可查看全部；每台设备关联一个宠物并单独标注共享属性；数据先只读展示；使用后台任务同步。

仍需产品／服务端确认的决定：

1. 认证方式已确定为用户名＋密码；需验证仅凭会话可持续查询、会话失效后的重连路径及支持区域，不再作为设计待选项。
2. 具体型号清单与字段单位／事件覆盖范围，尤其是饮水机有没有可验证的实际饮水数据。
3. 多宠共享是否首期就要求一台关联多个宠物；如需要，须增加关联模型及选择交互。
4. 是否要定时同步、同步频率和数据过期阈值；本稿首期默认进入时读缓存、用户手动同步。
5. 断开账号时提供删除历史选项；仍需确认保留期限、备份清除周期及正式隐私协议中的运营主体和联系方式。
