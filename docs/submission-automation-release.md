## 合并与发布交接

1. 前端发布负责人确认当前待发代码均已进入 dev；如 2.5.0 包有未推送修改，先提交入库，再合并本 PR，解决冲突后重新测试。
2. 统一从合并后的 dev 构建整包。小程序不会自动合并两位开发者上传的包。建议正式候选版本号 **2.5.1**，高于已核对的 2.4.0 和 2.5.0；本轮没有上传 2.5.1、切换体验版、提交审核或发布。
3. 上传时备注包含准确 Git SHA，例如 `需求18-20；commit=<合并后的SHA>`，并给该提交打与平台版本对应的发布 tag，建立可追溯关系。
4. 与团队协调后选择为体验版，使用专用验收账号验证正式后端。此前本地真实图、完整计算、真实通知及手机点击详情已通过；本地成功不替代合并后发布包的验收。
5. 通过后提交微信审核；审核通过再发布。后台正式通知目标当前为 formal，如需体验版通知验收，应由后端负责人协调临时目标及验收窗口，不能把 trial 当作独立测试数据库。
