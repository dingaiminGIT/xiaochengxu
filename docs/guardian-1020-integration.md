# case-1020 后端接口配套接入

本次同步交付需求 27、29 和 case 2 引起的小程序接口适配，不需要前端再次接线。

- 27：整体总结显示在逐款分析前；单品按 advantages/attentions 展示，保留旧接口 concerns 回退；按钮原样回传后端 slot/value/analysis_id。
- 29：聊天状态解读下可录入最近 14 天进食、饮水、排便次数。先读取已有值，PUT 当天绝对次数，保存成功后重新解读；支持手动记录/手填设备统计、过去日期完整日标记。未填为 null，实际 0 保留为 0；读取失败禁止覆盖。
- case 2：沿用原推荐卡，使用 recommendation_card 的短理由、留心项及阶段；提供查看详情、换一组，详情选择不会修改当前口粮。
- 历史口粮：原补录表单可搜索并显式关联已收录配方，当前粮 PATCH 与历史粮 POST 均传 product_id/formula_id。手工修改名字会清除原关联，避免挂错配方。
- 首页本机记录与聊天快照不再把未录入数量自动转换成 0，次数与克数/毫升分开。

这里只接入后端改动需要的交互；需求 24、25 的独立页面工作和 28 的狩猎广场导航仍由对应需求负责。

验证命令：

```bash
npm run test:contracts
npm run test:health-analysis
npm run test:guardian-1020
node scripts/check-assistant-chat.cjs
```

已用独立调试副本连接本地真实后端/数据库，通过微信开发者工具编译，并检查整体总结、确认推荐、次数保存和回显、推荐换组与详情、历史配方关联。开发者工具自动化的 DOM 查询/原生输入在当前版本不稳定，部分步骤通过页面事件处理器触发并核对实际接口和页面数据；不把这些检查当作真机验收。

正式 API 地址保持原配置。先部署配套后端，再合并本 PR 并走常规微信发布；本次创建 PR 不包含正式微信上传或发布。29 的品种/性别正常次数区间仍需要产品提供可核验参考表，目前按个体记录及完整日变化说明。
