# 云端提醒

入口：宠物 → 我的提醒。列表/历史、类型选择和新增/编辑沿用现有页面；首页读取同一账户的云端待办缓存。

`utils/reminder-api.js` 集中调用后端提醒 API，成功后才更新账户隔离的本机缓存。保存失败保留表单、完成失败保留待办；列表同步失败保留缓存并显示重试入口。请求中途切换账号时，旧响应不能覆盖新账号；旧 token 的 401 不能清除新登录态。

管家聊天通过 `client_context.capabilities.cloud_reminders_v1=true` 声明本版本有云端列表，识别内容和时间后保存同一云端提醒。仅新后端上线、旧小程序未发布时，聊天继续提示到旧提醒页面设置。

旧本机提醒显示“本机旧提醒”，用户明确点击导入并确认后才迁移。成功条目替换为云端，失败条目保留；重试使用稳定标识防止重复。原 `utils/reminders.js` 保留日期/周期函数和旧数据操作。

## 日历、重复与生日

两周日历、按日筛选和当期待办继续沿用。完成重复提醒时，服务端事务保存完成快照及下一未来周期，月底和闰年保留原始日期锚点；删除保留完成历史。编辑带读取时版本，避免其他设备更新后被旧表单覆盖。

宠物档案保存成功后调用生日同步接口，从后端档案创建一条年度生日提醒，默认 09:00；相同生日不重复创建，清除生日删除自动条目。2 月 29 日在平年为 2 月最后一天。生日同步失败明确提示，可在提醒页重试导入或重新保存档案。

提醒仅在小程序内展示待办和逾期，尚未接入系统通知、微信订阅消息或定时发送；云端条目支持登录同账号跨设备同步。后端统一按北京时间解释日期，返回毫秒时间戳。

接口：GET/POST `/api/miniprogram/reminders`，PATCH/DELETE `/{id}`，POST `/{id}/complete`，PUT `/api/miniprogram/cat-profiles/{id}/birthday-reminder`。鉴权、请求字段、幂等和完成重试详见后端 `docs/guardian-p0-api.md` 第 8 节。

验证：`node scripts/check-cloud-reminders.cjs` 覆盖 API 失败、账户切换、表单保留、稳定请求标识、完成历史、生日同步及明确导入；原本机周期与日期检查继续通过。真机和发布需小程序负责人验收。
